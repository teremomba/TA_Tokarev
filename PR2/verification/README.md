# Воспроизведение проверки

Готовые файлы открываются в JFLAP без запуска Java-кода. Для повторения автоматических проверок нужны JDK и оригинальный `JFLAP7.1.jar`.

Из каталога `PR2` в PowerShell можно выполнить команды, указав фактический путь к JAR:

```powershell
$jflapJar = 'C:/Users/Nikita/Desktop/JFLAP7.1.jar'
New-Item -ItemType Directory -Force -Path './verification/classes'
javac -encoding UTF-8 -cp $jflapJar -d './verification/classes' './verification/BuildVerifyPR2.java'
java '-Djava.awt.headless=true' -cp "./verification/classes;$jflapJar" BuildVerifyPR2 './verification/rebuilt'
```

Результат повторного запуска сохраняется в `verification/rebuilt`. Порядок раскрытия независимых меток конвертером может различаться; это не меняет язык и итоговые проверки.

Проверка использует XML-декодер, конвертеры и симулятор JFLAP 7.1. Ожидаемые результаты определяются отдельно по условию языка. Грамматика раскрывается полностью. Метки промежуточных обобщённых графов интерпретируются как регулярные выражения.

Состав протоколов:

- `verification.txt` — итоговые результаты.
- `exhaustive_results.tsv` — проверка всех 2047 цепочек длины от 0 до 10.
- `grammar_language.txt` — все 16 цепочек грамматики.
- `re_steps.tsv` — размеры графов на этапах преобразования РВ.
- `grammar_to_re_steps.tsv` — последовательность исключения состояний.
- `derived_expression.txt` — результат обратного преобразования в РВ.
- `trainer_results.tsv` — проверки двух примеров тренажёра.
- `L29_pumping_checks.tsv` — числовая иллюстрация доказательства для 4960 разбиений.

В текстовых протоколах `EPS` обозначает пустую цепочку. Вводить буквы `EPS` в автомат не нужно. Перебор разбиений не заменяет формального доказательства из основного отчёта.
